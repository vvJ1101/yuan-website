# 官网全面审查、编辑部式升级与生产部署设计

## 目标

在保留 YUAN 官网现有业务事实、板块结构与品牌基调的前提下，完成技术质量审查、内容准确性修正、移动端与视觉体验优化，并安全部署到现有生产服务器。

## 实施顺序

工作拆为三个连续阶段，在同一功能分支完成并在最终统一上线：

1. 技术审查与修复。
2. 内容及编辑部式视觉升级。
3. 完整验证、生产部署与线上回归。

技术修复先建立稳定基线，视觉和内容随后在该基线上调整，避免重复返工。生产环境只接收通过全部检查的最终版本，不发布中间过渡版本。

## 内容边界

- 保留现有业务事实、业务结构、合作名单和页面板块。
- 修正事实错误、语义歧义、重复内容、语法问题和不专业表达。
- “合作品牌与买手”及“合作买手与买手店”的语义保持不变。
- 不凭空增加品牌数量、渠道数量、合作机构、城市覆盖或业务成果。
- 涉及无法从现有资料核实的数字或资格时，优先弱化绝对表述，不自行推断。
- 官网不保存或公开订货政策、内部模板、服务器凭据及其他内部数据。

## 视觉方向

采用已确认的 A 方案“编辑部升级”：延续当前黑白与暖灰色调、时尚图片和克制品牌气质，不进行大规模品牌重构。

主要调整：

- 建立一致的标题、正文、标签和数字字号层级。
- 增加必要留白，减少密集文本带来的阅读压力。
- 统一图片比例、裁切策略、说明文字与区块节奏。
- 强化首屏定位、核心服务、合作品牌与买手、Showroom 和联系入口之间的视觉主次。
- 移动端优先保证标题换行、按钮触控范围、导航、图片焦点和长文段可读性。
- 动效尊重 `prefers-reduced-motion`，不以持续动画妨碍阅读。

视觉伴随稿保存在本地 `.superpowers/`，不提交 Git，也不部署生产环境。

## 技术审查与修复

### 移动端

- 覆盖常见手机、平板、笔记本和宽屏断点。
- 检查无横向溢出、文字截断、图片焦点错误和固定元素遮挡。
- 导航支持打开、关闭、Esc 键、焦点返回和页面跳转后自动收起。
- 交互控件满足至少 44×44 CSS 像素的移动触控目标。

### SEO

- 每页提供唯一且准确的标题、描述、canonical 与 Open Graph 信息。
- 首页结构化数据与页面真实联系方式、域名和组织名称一致。
- `robots.txt` 与 `sitemap.xml` 只公开真实存在且允许索引的页面。
- 标题结构保持单一 `h1` 和有序的章节层级。

### 性能

- 首屏关键图片使用适当优先级、尺寸和响应式资源。
- 非首屏图片延迟加载，并提供固定尺寸或比例以减少布局偏移。
- 删除未使用资源前必须通过引用审计，不凭文件名猜测。
- 控制客户端组件和动画范围，避免不必要的 hydration 与主线程开销。
- 以生产构建和浏览器测量为准记录主要性能问题，不承诺未经测量的分数。

### 安全

- 保持 `poweredByHeader: false`。
- 审查 CSP、点击劫持防护、MIME 嗅探、Referrer Policy、Permissions Policy 和 HTTPS 升级策略。
- 官网不引入内部 API、政策静态文件、环境密钥或服务器配置文件。
- 外部链接在新窗口打开时使用安全的 `rel` 属性。
- 部署包排除 `.env*`、Git 元数据、测试产物、本地视觉伴随文件和内部资料。

### 可访问性

- 使用语义化导航、主内容、章节、页脚和按钮元素。
- 图片提供与用途一致的替代文本；纯装饰图使用空替代文本。
- 所有功能可通过键盘操作，焦点样式清晰且顺序合理。
- 文本和控件颜色满足可读对比度，状态不只依赖颜色表达。
- 支持减少动态效果，并避免自动播放影响阅读。

## 组件与数据边界

`src/data/home.ts` 继续作为首页可编辑内容的单一来源。各 `section-*` 组件只负责展示对应数据，导航组件负责全站定位与移动交互，`layout.tsx` 负责全局元数据和结构化数据，`next.config.js` 负责安全响应头与框架配置。

不引入 CMS、数据库或新的后端接口。联系入口仍使用现有邮件和页内定位，不在本阶段增加表单数据收集。

## 错误与降级

- 图片加载失败不得破坏区块布局；关键品牌信息仍以文字存在。
- JavaScript 动效不可用时，核心内容和导航仍可阅读与访问。
- 构建、健康检查或线上回归任一失败时停止发布并恢复部署前构建。
- 域名、Nginx 或证书配置若与记录不一致，先保留现网配置并停止自动修改。

## 自动化与人工验证

扩充现有 Node 契约测试，覆盖：

- 内容语义、链接与公开数据边界。
- SEO 元数据、canonical、站点地图和 robots。
- 安全响应头配置。
- 导航键盘状态与移动交互标记。
- 图片尺寸、替代文本和高风险性能模式。
- 页面标题层级和主要地标。

完整验证命令为：

```bash
npm run test
npm run lint
npm run typecheck
npm run build
git diff --check
```

浏览器回归至少覆盖桌面宽屏、笔记本、390px 手机和 320px 小屏，检查首屏、导航、所有区块、联系入口、404 页面、控制台错误和网络失败。

## Git 与敏感信息

实现使用 `agent/website-audit-editorial-deployment` 分支。提交按技术修复、内容视觉、部署文档分开，便于独立审查和回滚。提交前运行敏感信息扫描；`.env*`、SSH 密钥、JWT/API 密钥、订货政策、内部模板和 `.superpowers/` 不得进入 Git。

通过验证后推送分支并合并到 `main`。生产部署只使用已推送且可追溯的提交。

## 生产部署

生产目标：

- 服务器：`120.79.162.27`
- 项目目录：`/var/www/yuan-website`
- PM2 进程：`yuan-website`
- 应用端口：`3002`
- 域名：`yuanshowroom.cn`、`www.yuanshowroom.cn`
- Nginx：继续反向代理到 `127.0.0.1:3002`

部署前记录当前 Git 提交和 Next.js `BUILD_ID`，备份现有 `.next` 与进程配置。上传新构建后验证 `BUILD_ID`、PM2 在线状态、本机端口 200、HTTPS 首页 200、安全响应头和静态资源。任一关键检查失败则恢复旧 `.next` 并重启原进程。

部署完成后执行桌面与移动端线上回归，不修改 Academy 进程、端口、数据目录或 Nginx 的 Academy server block。

## 验收标准

- 所有自动化检查退出码为 0。
- 桌面和移动端不存在阻断使用的布局、导航或可访问性问题。
- 内容未改变未经确认的业务事实，合作买手语义准确。
- 生产官网返回 200，PM2 稳定在线，HTTPS 与安全响应头正常。
- Git 和部署包中不存在订货政策、凭据或本地视觉伴随文件。
- Academy 服务与数据在官网部署前后保持不变。
